What you build

  • For Sawaqi, or for a comparable text task of your own with synthetic data.

  • Extraction that is masked, validated and scored by field.

The reply on the slide shows the shape of a decision; its values are illustrative. The starter in labs/capstone/ is Lab 3.4's service as one file with an evaluation script. A task of the participant's own is allowed when it has the same shape: at least two language varieties, at least five classes, fields to extract, a split by the unit that repeats, and data generated with a fixed seed. No real personal data in any file or prompt.

The first criterion, 25 points. A table with one average and no columns by variety loses most of them, as does a missing baseline row. A recommendation that does not follow from the table loses the rest: "the baseline, with a hand-off for Arabizi" is a full-marks answer if the table says so.

Two criteria, 20 points each

Extraction and adaptation are scored on their evidence

Extraction

  • A masking test that passes: no account or phone number leaves.
  • A schema whose validators reject wrong values.
  • Precision and recall for each field, next to a pattern baseline.
  • The log of validation failures, with what the service did.

Adaptation

  • A full fine-tuning run and a low-rank adapter run, same split.
  • Trainable-parameter counts and the memory budget.
  • Training logs with timestamps; the epoch chosen on validation.
  • Test scores for both, by variety, and which one you would keep.

Neither criterion asks for the neural model to win. Extraction is scored on masking, validation and field-level measurement; adaptation on the comparison and its logs. Text sent to a hosted model without masking costs marks under extraction whatever the scores are.

Pass: 70% overall, and at least 60% on this rubric. The repository is 60% of the result, the defence 20%, the supervised checks 20%.

Service and model card: the service runs, passes the smoke test, and the card states results by variety and the hand-off rule in words a contact-centre lead can act on. Reproducibility: a clean clone runs with uv run, the seed is fixed, and every number in the README has a committed, timestamped log behind it. The supervised checks are the entry and exit checks without AI assistance.

The defence

Eight minutes, then four minutes of questions

3 min · the table

The task, the three rows by variety, and your recommendation.

3 min · a re-score

The assessor gives a labelled batch you have not seen. Score your served model on it, live.

2 min · two errors

Two messages from that batch your model got wrong: the cause of each, and the remedy.

AI assistants were allowed in full. The defence is where you show that the decisions are yours.

Assessors: for Sawaqi, draw a batch of 20 to 40 labelled messages with prepare_data.py under another seed, in the columns msg_id, text, variety, department; the participant runs capstone/evaluate.py --batch on it. For a task of the participant's own, ask for their generator a day ahead and draw the batch from it yourself. If the re-score differs much from the README, that is the conversation: a calm explanation (small batch, another variety mix) scores well; a test split that chose a threshold does not.

Before you publish

Four things that cost marks, each checkable in a minute

No baseline row, or no varieties

One average hides the group the model fails.

The test split chose something

A threshold, a prompt, an epoch or a learning rate.

Unmasked text left the machine

An account or phone number in a prompt or a log.

A number with no log

Every figure in the README points at a committed file.

Ask the participants to check each other's repositories against these four before the deadline: five minutes in pairs. A search of the repository for the pattern of an account number finds the third one quickly.

Final preparation

Ten minutes: clone it clean, run the smoke test

Clone your public repository into a new folder, run the smoke test and re-score the example batch. If that fails, the assessor's batch will too.

The clean-clone test catches most reproducibility losses: a model file that was never committed, a key in a local file, a path that only exists on the participant's laptop.

Now defending

Defence

Questions

Start the first timer when the participant starts speaking: three, three and two minutes. Start the second for the questions. Hand over the batch file at the start of the re-score, not before.

After the defences

The weakest variety

The re-score gap

Whose unseen batch came closest to their README, and why?

Ten minutes. Ask participants to name one decision of another participant that they would copy.
